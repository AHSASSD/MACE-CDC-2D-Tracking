## 2. 数据准备与异步传输

测试了0、1、2个加载进程，选择2个。加载进程采用spawn，persistent_workers开启，每个进程预取2批；固定CPU内存，独立CUDA流提前传输下一批，并记录流依赖保护张量生命周期。主进程Torch线程1，与2个加载进程配合3核分配。

验证阶段同样读取缓存和预取，不再重算图。单独测试验证batch8/16/32，吞吐约40.70/38.37/31.49事件每秒，因此验证采用8。

## 3. 部分激活重算

固定取消第一层重算的方案，在batch8最密集图压力测试中显存不足，未采用。

采用按边数自适应方案：7次节点更新中，前 `min(3, floor(1500000 / 本批边数))` 次直接保存激活，其余仍重算；最后的边分类继续分块重算。边数很大的批次自动全部保留重算；没有关闭所有重算，也没有删除候选边。单元检查证明输出与梯度和原方案等价。

## 4. 端到端联合测试

全部训练对照使用同一64个训练事件，包含磁盘读取、CPU拼批、固定内存、H2D、前向、反向、梯度累积与优化器更新。每配置预热一次、测量两次。有效批量都是32。压力测试按完整7000事件候选边数排序，采用最大的图组成批次；显存筛选限26GiB，为其他缓冲留出余量。测试不依据独立test分数选运行策略。

| 方案 | 事件/秒 |
|---|---:|
| 原流程，逐次构图、batch8、分块65536、全重算 | 8.48 |
| 只加入图缓存 | 12.08 |
| 缓存＋1加载进程＋预取/异步传输 | 13.55 |
| 缓存＋2加载进程＋预取/异步传输 | 13.78 |
| 再加自适应部分重算，batch8/分块65536 | 14.71 |
| 最终：batch4/分块131072/自适应重算 | **16.34** |

最终配置：训练batch4、累积8步、有效批量32、验证batch8、分块131072、加载进程2。训练短测相对原流程约1.93倍。最大边数批次的压力测试峰值分配显存约7.75GiB；又补查了50万、75万、150万边的自适应切换边界，最大约11.9GiB，梯度均为有限值。这些指标只包含PyTorch分配，不等于nvidia-smi整卡占用。batch16更慢，部分大分块配置显存不足。

该结果是包含完整训练步骤的固定样本对照，不是完整epoch的速度保证；整轮吞吐还受事件分布、文件页缓存和共享存储影响。后续实际速度以新训练日志为准。
